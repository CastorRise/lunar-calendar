# 农历日历

一个在浏览器中运行的公历、农历转换和日历事件导出工具。选择农历纪念日后，可以逐年推算对应公历日期，检查闰月和小月的处理结果，再将选中的日期导出为 ICS 文件。日期计算、设置和文件生成均在本地完成，无需账号或后端。

## 启动与构建

需要 Node.js 22 和 npm。在项目目录运行：

```sh
npm ci
npm run dev
```

打开终端显示的本地地址。其他命令：

```sh
npm test          # 运行核心逻辑测试
npm run build     # 类型检查并构建到 dist/
npm run preview   # 本地预览生产构建
```

## 使用

1. 在「日期转换」中选择公历或农历日期。日期和时间按中国标准时间（UTC+8）解释；可以将转换结果带入未来推算。
2. 在「未来推算」中设置起始农历年、月日及年数。年数包含起始年：例如从 2026 年推算 10 年，处理农历 2026 至 2035 年。闰月不存在或农历三十落在小月时，默认跳过；选择替代策略后，结果会标明调整。可以在列表或月历视图中选择事件。
3. 在「日历导出」中设置名称、全天或指定时间、时区、提醒和备注，检查预览后导出。每个日期生成独立的 VEVENT，没有用公历年度重复规则代替农历规则。全天事件的结束日为排他日期；指定时间按选择的 IANA 时区转换为 UTC。夏令时切换导致不存在或重复的本地时间会提示修改。

ICS 是一次性导入文件，不会自动同步未来新增的年份。日历应用对提醒、导入及重复导入的处理可能不同；建议先用少量事件在目标应用中检查，再导入完整文件。事件设置和最近输入保存在浏览器的 localStorage，清除站点数据会删除这些设置。

## 农历计算范围与准确性

本项目使用 `lunar-javascript`。应用主动限制完整农历年 **1901–2099**，对应可转换的公历日期 **1901-02-19 至 2100-02-08**；未来推算的最后一个农历年份也不能超过 2099 年。范围外的日期不会生成结果。

测试覆盖所有支持农历年份每月的首日、末日双向往返，并使用包括农历新年、闰月和跨公历年在内的已知日期样例。另对照[香港天文台公开的逐日数据](https://data.gov.hk/en-data/dataset/hk-hko-rss-gregorian-lunar-calendar-conversion-table)，2023–2028 年共 2,192 天的农历月日和闰月标记一致。上述对照和往返测试不等于逐日验证整个支持范围。

香港天文台指出，远期新月接近午夜时，计算不确定性可能导致农历月份日期相差一天，例如 2057、2089 和 2097 年的部分新月；详见其[公历与农历日期对照表说明](https://www.hko.gov.hk/en/gts/time/conversion.htm)。长期安排可在临近日期时重新核对。

## 部署到 GitHub Pages

仓库包含 `.github/workflows/deploy.yml`：推送到 `main` 或手动运行工作流时，先安装依赖、测试和构建，再部署 `dist/`。在仓库 **Settings → Pages** 中，将构建来源选择为 **GitHub Actions**。Vite 的 `base: './'` 使用相对资源路径，适用于仓库子路径。创建仓库、推送和启用 Pages 需要自行完成。

## 限制

- 生产构建包含 Service Worker，在 HTTPS 或 localhost 环境下首次联网加载后尝试缓存页面与资源，之后可离线使用；首次访问仍需网络，浏览器清除缓存或不支持 Service Worker 时离线访问不可保证。
- 指定时间事件的开始和结束时间须在同一天，暂不支持跨日或多日定时事件。
- ICS 生成逻辑有自动化测试；具体 Apple 日历、Google Calendar、Outlook 版本的实际导入、提醒显示和分享菜单行为需要分别验证。
- 复制、下载和系统分享依赖浏览器能力及权限；某些环境可能不可用。

## 代码结构

- `src/lunar.ts`：日期校验、双向转换及未来年份推算。
- `src/ics.ts`：事件时间、时区及 RFC 5545 内容生成。
- `src/main.tsx`、`src/style.css`：界面、交互与样式。
- `src/*.test.ts`：日期转换和 ICS 的核心测试。
- `public/sw.js`：生产环境离线缓存。
- `.github/workflows/`：GitHub Pages 构建与部署工作流。
